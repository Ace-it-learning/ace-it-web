# Ace It! Math Topic Implementation Guide

This guide outlines the standard procedures and patterns for adding or modifying mathematical topics in the Ace It! platform. Use these "tricks of the trade" to ensure consistency and prevent common regressions.

## 1. Topic Normalization Map
Always ensure the topic shorthand from the frontend (e.g., "percentage") is mapped to the standard Database ID in `MathsLabService.js`.

**Location**: `MathsLabService.js` -> `topicMap`
```javascript
const topicMap = {
    'percentages': 'math_num_percentages',
    'circle properties': 'math_geo_circles',
    'coordinate geometry': 'math_geo_coord',
    // ADD NEW TOPICS HERE
};
```

## 2. Difficulty Tier Synchronization
The frontend uses tiers 1-4, which must be mapped to the backend question bank levels (3, 4, 5, 7).

| Frontend Tier | Backend Level | Description |
| :--- | :--- | :--- |
| 1 | 3 | Easy (Level 3 standard) |
| 2 | 4 | Medium (Level 4 standard) |
| 3 | 5 | DSE Standard (Level 5) |
| 4 | 7 | Elite (Level 5**/7) |

## 3. Delimiter & LaTeX Standards
We use a "hard-then-soft" approach to math rendering:
1. **Gemini Instructions**: Enforce `$` for inline and `$$` for display math.
2. **Post-Processing**: `MathsLabService.postProcessMathText` acts as a safety net to:
   - Fix "orphan" delimiters (e.g., `\)` without `\(`).
   - Inject "Neutral Zone" spaces between text and math.
   - Clean up AI "monologue" (e.g., "Let me recalculate...").
   - Strip colons/trailing punctuation *out* of math tags to prevent rendering artifacts.

## 4. Engine Selection: AI vs. Python Seeds
- **AI Generator**: Best for Algebra and word problems with simple logic.
- **Python Seed (`python-seed`)**: Required for Geometry/Trig topics where specific numeric configurations (e.g., side lengths, angles) are needed to ensure geometric validity.
- **Graphing**: Add topics to `graphTopics` in `needsMatplotlibGraph` to enable automated SVG/PNG generation via Python.

## 5. Local Dev Troubleshooting (The "Access" Issue)
If you "suddenly can't access" the dashboard on localhost, it is usually one of two things:
1. **Email Verification**: A new/reset account isn't marked as `emailVerified: true` in Firebase. This causes `ProtectedRoute.jsx` to redirect to `/login`.
2. **Vite Proxy Collision**: Ensure `vite.config.js` has `hmr` at the `server` level, not nested inside `proxy`.

> [!TIP]

## 6. Quest Persistence & Exhaustion Logic (v2.0)
To ensure students are never served repeated or unapproved questions unexpectedly, follow these structural rules:

1. **"Mark-on-Serve" Persistence**:
   - **Rule**: Call `markQuestionsSeen(uid, questionIds)` the *moment* questions are fetched from the bank or generated by AI.
   - **Rationale**: This treats served questions as "forfeited" if the student abandons the session, preventing them from being re-served in the next session.

2. **Bank Exhaustion Detection**:
   - **Rule**: If the count of unseen approved questions is less than `TARGET_COUNT` (default 5), the backend MUST return a `BANK_EMPTY_SEEN` error.
   - **Prompt**: This triggers the "Bank Completed!" UI prompt, giving the student the choice to Review or Generate New.

3. **Review Mode Fallback**:
   - **Rule**: If `mode === 'review'`, the system MUST bypass the "seen" filter and pull randomly from the `seenApprovedQuestions` pool.
   - **Logic**: Ensure this bypass happens *before* the exhaustion check to avoid a recursive prompt loop.

4. **"Gold Standard" Python Seeds**:
   - **Rule**: For topics requiring high-fidelity diagrams (e.g., Coordinate Geometry, Circle Properties), always use `engine: 'python-seed'`.
   - **Diagrams**: The Python script should pre-render the SVG or provide a robust `diagram_json` to eliminate AI diagram hallucinations.

5. **Rendering Robustness (Frontend)**:
   - **Rule**: All geometry/chart renderers must use strict `Array.isArray()` validation for all data loops (points, lines, etc.).
   - **Safety**: Provide default numeric ranges (e.g., `x_range: [-5, 5]`) to prevent `NaN` crashes if the AI provides incomplete metadata.

## 7. Database Attribute Standards ("Gold Standard")
To ensure compatibility with the `question_bank` collection and the bilingual frontend, all generated/seeded questions MUST strictly follow this attribute schema:

### Mandatory Fields
| Attribute | Type | Description |
| :--- | :--- | :--- |
| `id` | String | Unique serial identifier (e.g., `poly_01`). |
| `topic` | String | Human-readable topic name (e.g., `Polynomials`). |
| `topic_id` | String | Matching the `topicMap` Database ID in `MathsLabService.js`. |
| `subject` | String | Fixed value: `maths`. |
| `level` | Number | Integer complexity level: 3 (Easy), 4 (Medium), 5 (DSE), 7 (Elite/Section B). |
| `type` | String | Usually `short_answer` for curated factory seeds. |
| `marks` | Number | Standardized scoring: 2 (L3), 3 (L4), 4 (L5/L7). |
| `is_approved`| Boolean | **CRITICAL**: Must be `true` for questions to be visible in Practice Lab. |
| `is_factory` | Boolean | Set to `true` for questions from the Python central bank. |
| `question` | String | English question text. Use `$` for inline math, `$$` for block math. |
| `question_zh` | String | Traditional Chinese question text. LaTeX must be identical to English. |
| `answer` | String | Final correct result in LaTeX form. |
| `correct_answer`| String | Redundant field mirroring `answer` for legacy verification logic. |
| `solution_steps` | Array | Array of strings (English). Each element is one step. |
| `solution_steps_zh`| Array | Array of strings (Chinese). Must correspond 1:1 with English steps. |
| `diagram_svg` | String | (Optional) Full `<svg>...</svg>` string for visual/geometric questions. |

### Sample JSON Reference
Use this template when creating new `_final.json` or seeding scripts:

```json
{
  "id": "poly_01",
  "topic": "Polynomials",
  "topic_id": "math_alg_polynomials",
  "subject": "maths",
  "level": 3,
  "type": "short_answer",
  "marks": 2,
  "is_approved": true,
  "is_factory": true,
  "question": "Find the remainder when $f(x) = x^2 + 5$ is divided by $x-1$.",
  "question_zh": "求多項式 $f(x) = x^2 + 5$ 除以 $x-1$ 時的餘數。",
  "answer": "6",
  "correct_answer": "6",
  "solution_steps": [
    "By Remainder Theorem, substitute $x=1$.",
    "$f(1) = (1)^2 + 5 = 6$."
  ],
  "solution_steps_zh": [
    "根據餘式定理，代入 $x=1$。",
    "$f(1) = (1)^2 + 5 = 6$。"
  ]
}
```

## 8. Antigravity Direct Assessment (v4.0)
For handwritten submissions, we use the **Direct Multimodal Assessment** protocol to ensure maximum logic-checking accuracy and line-by-line feedback.

### **The Protocol**
- **Engine**: Antigravity (as an Elite AI Examiner).
- **Process**: Single-pass multimodal Vision assessment.
- **Inputs**: `imageBuffer`, `contentType`, and `problemContext` (Question, Steps, Answer, Marks).

### **JSON Requirements**
The AI must return a structured grading report including:
- `marks_awarded`: Integer based on M and A marks.
- `transcribed_final_answer`: Student's final value in LaTeX.
- `error_step_description`: Precise localization of any logical breakdown.
- `rubric_breakdown`: Line-by-line justification for marks awarded.

> [!IMPORTANT]
> This protocol replaces the previous "Parser-then-Grader" pipeline to provide faster, more accurate direct feedback on handwriting without intermediate digital conversion.
